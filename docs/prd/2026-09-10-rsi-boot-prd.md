## 1. 产品定位

**RSI Boot** 是一个面向个人开发者的本地 MCP 工具（与 Superpowers 同类：pip 安装、IDE 注册即用、零外部服务依赖）。它不训练大模型，而是通过统一模型接入、上下文增强、交互反馈和学习闭环，让通用大模型在用户的每个项目中表现持续优化，逐步成为「越用越懂你」的专职 AI 助手。

「RSI」取自 **Recursive Self-Improvement（递归自我改进）**，走 **Harness-RSI** 路线（2026 年 MetaRSI-v1 / Self-Harness / AHE 等前沿实践）：不改模型权重，而是把包裹模型的 Harness——提示词模板、策略、知识库、画像、工具——作为可写面，从执行轨迹中挖掘失败模式，自动生成最小化改进提案，经回归验证与人工确认后晋升，并可一键回滚（详见 Spec §3.9）。

### 产品 slogan

> *Build once, route smartly, improve continuously — without retraining.*

### 设计原则

- **安装即用**：`pip install rsi-boot` + IDE 注册一次 MCP Server，无需任何服务端部署
- **零运维**：全部数据存项目 `.rsi/` 目录（SQLite 单文件），无 PostgreSQL/Redis/向量库服务
- **功能全**：意图路由、知识检索、用户画像、反馈学习、项目自学习、成本意识一应俱全
- **稳定**：熔断/重试/降级链保证 LLM 或本地依赖故障时优雅退化，不阻塞开发流

## 2. 目标用户

| 用户角色 | 核心诉求 | 使用方式 |
|----------|----------|----------|
| **开发者** | 在 IDE/CLI 中获得更符合项目上下文的高质量代码建议 | MCP 客户端（IDE 插件、CLI 工具） |
| **测试工程师** | 生成测试用例、审查测试质量、分析 Bug 根因 | MCP 客户端（IDE 插件、CLI 工具） |
| **产品经理** | 生成 PRD 草稿、审查需求文档、数据分析 | MCP 客户端（文档工具、CLI 工具） |
| **项目维护者** | 沉淀项目知识，让 AI 回复包含项目特有文档和规范 | 知识库管理 / 反馈标注 |

> 均为同一人的不同角色侧面——RSI Boot 是单用户工具，「角色」指使用者当前的工作身份（developer/test/pm），用于意图路由与知识检索，不含权限语义。

## 3. 核心场景

### 场景 A：工作产出辅助（核心场景）

> 用户在编辑器中选中一段内容（代码/测试用例/需求文档），
> 通过 RSI Boot 获得审查、优化建议或新内容生成。

**示例-开发者**：在 IDE 中选中代码段，获得代码审查或优化建议。
**示例-测试工程师**：在 IDE 中选中测试用例，获得边界条件补充或测试质量审查。
**示例-产品经理**：在文档中选中功能描述，获得 PRD 模板生成或需求分析。

**期望**：回复引用项目特有规范（命名约定/测试规范/需求模板）、历史相似实现，而非泛泛的通用建议。

**成功标准**：内容采纳率 > 60%（各角色独立统计），上下文相关性评分 > 0.8。

### 场景 B：项目文档问答

> 用户向 RSI Boot 提问项目架构、部署流程、测试规范或产品文档，工具结合项目知识库回答。

**示例-开发者**：「这个项目的数据库迁移流程是什么?」，检索项目 README 和 ADR 记录回答。
**示例-测试工程师**：「这个接口的测试环境怎么搭建?」，检索测试环境配置文档回答。
**示例-产品经理**：「当前版本发布了哪些功能?」，检索 Changelog 和 Release Notes 回答。

**期望**：回答准确引用项目文档，可溯源，幻觉率 < 5%。角色感知：不同角色提问时，优先检索对应领域（devops/docs/test/product）的知识条目。

**成功标准**：知识检索命中率 > 85%，回答准确率 > 90%（各角色独立统计）。

### 场景 C：个人多项目统一 AI 助手

> 用户一次配置模型和偏好，所有项目窗口自动获得一致的 AI 助手体验；每个项目的知识库与画像独立，通用偏好跨项目沉淀。

**示例**：用户在项目 A 习惯 pytest 风格，切到项目 B 时全局画像自动带上该偏好；项目 B 的专有知识（如其特有的测试环境文档）只在项目 B 内生效。

**期望**：按意图+角色路由不同模型（如简单问题用便宜模型，专业生成用高性能模型）；个人 token 用量与成本可按日/周/月自查（`rsi_stats`）。

**成功标准**：相比无路由直连单一高价模型的成本节省 > 30%；跨项目切换零配置。

## 4. 功能优先级 (MoSCoW)

### Phase 1 — Must Have (基础链路)

Phase 1 拆分为两个里程碑（M1/M2），M1 聚焦核心推理链路（2-3 周），M2 补全数据与协议能力（2-4 周）。

#### M1：核心链路（2-3 周）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| MCP 协议接入 | 以 MCP Server 形式暴露（stdio），客户端自动发现工具 | P0 |
| rsi_query 工具 | 统一查询入口，接收标准化请求，返回标准化响应 | P0 |
| 请求预处理 | 意图识别（规则版）+ 基础上下文组装 | P0 |
| 策略引擎 | 基于意图的模型/模板路由，固定策略配置 | P0 |
| 模型适配层 | 接入至少 1 个 LLM（OpenAI），统一调用接口 | P0 |
| 响应后处理 | 模型输出解析、格式化为标准 RSIResponse | P0 |
| 编排器（Pipeline 模式） | 协调预处理→策略→模型→后处理全流程 | P0 |
| 交互日志 | 记录请求/响应的关键字段到 SQLite（`.rsi/rsi.db`） | P0 |
| 配置管理 | Pydantic Settings + YAML 类型安全配置 | P0 |
| 错误处理 | 熔断器、指数退避重试、降级策略 | P0 |

#### M2：数据与协议完善（2-4 周）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 数据脱敏 | 日志脱敏（API key、用户敏感信息）；外发 LLM 前密钥扫描 | P0 |
| 数据生命周期 | 日志保留策略（90 天）、数据导出、删除机制 | P0 |
| 数据库迁移 | PRAGMA user_version + migrations/ 顺序 SQL 脚本，幂等可重入 | P0 |
| MCP 协议完善 | 完整实现 initialize/tools/list/tools/call 等方法 | P0 |
| 角色感知基础设施 | RSIRequest.role 字段、config/roles/ 目录加载、角色维度日志 | P1 |
| rsi bootstrap 项目自学习 | 自动扫描项目 9 类信号源，生成初始知识库与用户画像；分两期交付——核心扫描层（M2：信号发现/文档/配置/画像/CLI）+ 深度信号层（Phase 2：代码 AST/Git 历史/对话上下文/关联推理/增量监听）（详见 §9.3 与 Spec §10.9） | P1 |

### Phase 2 — Should Have (知识增强)

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 向量检索集成 | sqlite-vec 接入（与主库同文件），知识条目 CRUD | P1 |
| 意图识别升级 | 基于分类模型（如 few-shot）提升准确率 | P1 |
| 知识检索与注入 | 检索相关文档并注入提示词上下文；M1 交付 FTS5-only 子集（手动种子），Phase 2 升级 FTS5 + 向量混合检索（RRF） | P1 |
| 用户画像基础 | 画像存储与读取，支持项目级配置 | P1 |

| 功能 | 说明 | 优先级 |

## 6. 非功能需求

| 需求 | 要求 |
|------|------|
| **安全性** | 日志脱敏（API key、用户敏感信息）；外发 LLM 前密钥/Token/内网地址扫描；LLM API Key 仅走环境变量，禁止写入项目配置文件；可选字段级加密（AES-256-GCM，默认关闭） |
| **可观测性** | 全链路日志（请求/响应/错误）落本地 SQLite；结构化日志（JSON 格式）；支持流式响应 SSE |
| **可扩展性** | 模型适配器可插拔；策略引擎可配置；角色/意图插件化注册 |
| **可测试性** | 所有核心模块契约可 mock；支持 CI 自动化测试（临时目录 SQLite，无外部服务依赖） |
| **可维护性** | 遵循 SDD 规范驱动；模块文档齐全；代码规范统一 |
| **数据生命周期** | 日志 90 天保留期（过期导出 `.rsi/archive/` 后删除）；支持数据导出（JSON/CSV）；卸载即删 `.rsi/` 目录完成全部数据清除 |
| **部署轻量化** | 零外部服务依赖：SQLite 单文件 + sqlite-vec + FTS5 全内嵌；pip 安装即用；进程内存占用 < 200MB（不含模型） |

## 7. 约束与假设

- **不训练模型**：所有改进均通过外部手段（提示词优化、检索增强、路由策略）实现
- **协议标准**：所有外部接口遵循 MCP 协议（JSON-RPC 2.0）
- **向后兼容**：工具接口一旦发布，变更通过新增版本而非修改旧版
- **数据主权**：全部数据存本机 `.rsi/` 与 `~/.rsi/`，不上传任何远端。注意：请求内容（含代码片段）会发送至所配置的 LLM 提供商，其数据使用政策由提供商约束；对代码外发有顾虑时可仅接入私有部署模型端点（Phase 4 多模型适配后）
- **单用户**：本人使用，无协同、无权限体系；user_id 取 `git config user.email` 仅用于画像归属
- **流式响应**：模型调用支持 SSE 流式输出
- **知识库可信度**：检索结果显式标注来源文档；低置信度（向量 cosine 相似度 < 0.6，见 Spec §3.2）不注入上下文
- **MCP 传输**：仅 stdio（本地进程管道），无网络监听

## 9. 集成方案（Integration Scheme）

> **一句话定义**：RSI Boot 是一个 **Python CLI 工具（MCP Server 进程）**。它不是库/SDK（你的项目不用改代码），不是 SaaS（数据全在本机），不是 IDE 插件（但 IDE 可以通过 MCP 连它）。它由 IDE 按项目拉起，通过 stdio 与 IDE/CLI 通信。
>
> **对比理解**：
> - ❌ 不是 `pip install rsi-boot && import rsi` → 不改项目代码
> - ❌ 不是 订阅一个 SaaS 服务 → 数据存本地
> - ✅ 是 IDE 打开项目时自动拉起 `rsi start --stdio` 进程
>
> | 你做的事 | 等价行为 |
> |---------|---------|
> | `pip install rsi-boot` | 安装 CLI 工具 |
> | `cd my-project && rsi init` | 生成项目配置文件 |
> | `rsi bootstrap` | 自动扫描项目学习 |
> | IDE 配一次 MCP Server | 之后每个项目窗口自动拉起 |

### 9.1 集成形态：三层模型

```
┌──────────────────────────────────────────────────────────────────┐
│  第一层：项目级配置 (rsi-boot.yaml)                              │
│  存在位置：项目根目录，可纳入版本控制 (git-tracked)                │
│  职责：声明项目特征、默认角色、知识库来源、策略覆盖                 │
│  生命周期：与项目同生命周期                                        │
└──────────────────────────────────────────────────────────────────┘
         │  rsi init 自动生成，人工可编辑
         ▼
┌──────────────────────────────────────────────────────────────────┐
│  第二层：进程级服务 (rsi start --stdio)                          │
│  存在位置：开发机，由 IDE 按项目拉起的独立进程（cwd=项目根目录）    │
│  职责：MCP Server 核心——加载配置、连接模型 API、维护知识库、记录日志 │
│  生命周期：随 IDE 项目窗口启停                                     │
│  传输：stdio（本地管道，无网络端口）                               │
└──────────────────────────────────────────────────────────────────┘
         │  IDE 通过 MCP 协议连接（stdio）
         ▼
┌──────────────────────────────────────────────────────────────────┐
│  第三层：IDE/CLI 级工具 (MCP Client)                             │
│  存在位置：VS Code / JetBrains / Cursor / 终端 CLI                │
│  职责：用户交互界面——发起查询、接收响应、提交反馈                    │
│  配置：.vscode/mcp.json 或 JetBrains MCP 插件设置                  │
└──────────────────────────────────────────────────────────────────┘
```

**一句话总结**：
- **项目里**放一个 YAML 配置（可选）→ 告诉 RSI 这个项目是谁
- **IDE 里**配一次 MCP Server → 每个项目窗口自动拉起独立进程
- **数据**落在项目 `.rsi/` 目录 → 删目录即彻底卸载项目数据

### 9.2 运行拓扑

#### 常规：本地模式（个人开发）

```
┌───────────────┐      stdio       ┌──────────────────┐
│  开发机        │ ◄──────────────► │  RSI Boot         │
│  VS Code       │                  │  (本地进程)        │
│  + MCP Client  │                  │  ├ .rsi/rsi.db    │
└───────────────┘                  │  ├ 画像/知识库     │
                                   │  └ LLM API ◄──► 外部(HTTPS)
                                   └──────────────────┘
```

- 安装：`pip install rsi-boot`
- 初始化：`cd my-project && rsi init && rsi bootstrap (强烈建议)`
- 启动：IDE 自动拉起（手动调试用 `rsi start`）
- 数据存储：`.rsi/` 目录（SQLite + sqlite-vec 向量 + FTS5）
- IDE 配置：`.vscode/mcp.json` 指向 `rsi start --stdio`

#### CI/CD 模式（自动化）

```
CI Pipeline
┌──────────────┐     rsi query (stdio)      ┌────────────────┐
│  pytest      │ ◄─────────────────────────►│  RSI Boot      │
│  lint        │    用完即销毁               │  (临时进程)     │
│  code review │                            │  零持久化       │
└──────────────┘                            └────────────────┘
```

- 安装：`pip install rsi-boot`
- 调用：CI 脚本通过 `rsi query` 直接调用（冷启动，无历史数据依赖）
- 销毁：进程退出即清理

### 9.3 存量项目自学习（重要场景）

> **场景**：用户的项目可能运行了数月甚至数年，积累了代码、文档、Git 历史、对话记录、配置文件等多维信号。
> 如果从零开始积累知识库和画像，冷启动阶段会让 AI 回复缺乏项目认知，用户体验差。
> `rsi bootstrap` 命令会自动扫描项目全貌，从中学习所有可用的信号源，让工具第一天就具备项目认知。

```bash
# 标准流程——进入已有项目目录
cd my-existing-project

# 1. 生成配置文件
rsi init

# 2. (强烈建议) 一键自学习——扫描项目并自动学习
#    系统会自动发现文档、代码结构、Git 历史、对话上下文、配置规范等信号源
rsi bootstrap

# 3. 之后 IDE 打开项目即自动带监听启动（或手动 rsi start --watch）

# 4. 验证——此时工具已经对项目有全面认知
rsi query "这个项目的架构是什么？测试框架？代码风格？"
```

**`rsi bootstrap` 会做什么？**
- 自动发现项目中的信号源（无需用户指定）
- 文档扫描：`docs/**/*.md`、README、ADR → 向量化 → 知识库
- 代码骨架提取：AST 分析提取模块/类/函数/API 定义
- Git 历史分析：编码风格、贡献领域、开发习惯
- 对话上下文扫描：从 IDE 聊天记录中提取常见问题模式（需用户显式同意）
- 配置/规范解析：识别技术栈、构建工具、代码规范
- 跨信号源关联推理：理解「文档讲哪个模块」「测试覆盖哪块代码」
- 生成初始用户画像（包含技术栈/架构/测试习惯等多维度）

> 📎 详细自学习设计见 [Specs §10.9 项目自学习与初始化](../specs/2026-09-10-rsi-boot-spec.md#109-项目自学习与初始化project-bootstrap--auto-learn)

### 9.4 IDE 集成

用户在 IDE 中连接本项目拉起的 RSI Boot 进程，通过 MCP 协议交互：

| IDE | 连接方式 | 配置方法 |
|-----|---------|---------|
| VS Code | MCP stdio | `.vscode/mcp.json` 配置 `rsi start --stdio` 命令 |
| JetBrains | MCP stdio | MCP 插件配置启动命令 |
| Cursor | MCP 原生支持 | Cursor Settings → MCP Server |
| 任何 MCP 客户端 | stdio | 参考 MCP 协议规范连接 |

**交互方式**：
- **选中操作**：选中内容 → 右键 → RSI → 审查/优化/生成
- **对话查询**：打开 MCP 对话面板 → 输入问题 → 流式接收结果
- **CLI 直接调用**：`rsi query "..."`（终端中直接使用）

### 9.5 个人初始化流程

1. `pip install rsi-boot`，IDE 中注册一次 MCP Server（全局生效）
2. 进入项目：`rsi init` 生成 `rsi-boot.yaml`（可选，无配置也能跑）
3. (可选但强烈建议) `rsi bootstrap` 项目自学习——自动扫描文档/代码/Git/对话上下文
4. 在 `rsi-boot.yaml` 设置本人该项目的主要角色（`role.default`）
5. 正常使用，运行一段时间后用 `rsi_stats` 查看采纳率与用量基线

### 9.6 集成要点概括

```
RSI Boot 集成三部曲：

┌─────────────────────────────────────────────────────┐
│  1. 项目级别：rsi-boot.yaml  ← 告诉 RSI 项目是谁    │
│     - 放在项目根目录（可选），可纳入版本控制          │
│     - 声明语言/框架/默认角色/知识库来源               │
├─────────────────────────────────────────────────────┤
│  2. 进程级别：rsi start --stdio ← IDE 自动拉起      │
│     - 一个独立 Python 进程，随项目窗口启停            │
│     - 加载配置、连接 LLM、维护知识库、处理请求         │
│     - 仅 stdio，无网络端口                           │
├─────────────────────────────────────────────────────┤
│  3. 工具级别：MCP Client 连接   ← IDE/CLI 连上来     │
│     - VS Code：.vscode/mcp.json                     │
│     - JetBrains：MCP 插件配置                        │
│     - CLI：rsi query 命令内置连接                    │
└─────────────────────────────────────────────────────┘
```

> **关键区别**：RSI 不是 "import rsi" 进你的代码，而是 IDE 打开项目时在旁边拉起一个进程等着被连。
> 你的项目不需要做任何代码修改，也不需要引入任何依赖。

## 10. 风险与缓解措施

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|----------|
| OpenAI API 不稳定/限流 | 中 | 高 | 熔断器 + 重试；Phase 2 实现同厂商型号 fallback（gpt-4o → gpt-4o-mini），Phase 4 扩展跨厂商 fallback |
| 知识检索效果不如预期 | 中 | 中 | Phase 2 预留调优时间；混合检索参数可调 |
| 反馈率过低影响学习效果 | 高 | 中 | 优先完善隐式反馈；Phase 3 用模拟数据验证 |
| SQLite 可靠性（并发写/文件损坏） | 低 | 中 | WAL 模式 + 写锁重试；`PRAGMA integrity_check` 启动自检；损坏时自动备份重建（知识可重新索引） |
| 知识库冷启动 | 中 | 中 | 提供 `rsi bootstrap` 命令一键自学习（自动扫描文档/代码/Git/对话上下文等9类信号源）；支持种子脚本批量索引 |
| 用户对 AI 输出信任度低 | 中 | 高 | 显式标注来源；低置信度不注入；提供溯源能力 |
| 代码片段外发 LLM 顾虑 | 中 | 中 | 外发前密钥/内网地址脱敏扫描（Spec §8.1）；支持仅接入私有模型端点（Phase 4） |
