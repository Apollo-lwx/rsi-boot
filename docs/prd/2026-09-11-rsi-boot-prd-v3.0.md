## 1. 产品定位

**RSI Boot** 是一个面向个人开发者的本地 MCP 工具：**宿主 AI 的程序性记忆层**。它不调用模型生成答案，而是站在宿主模型（Cursor 等 IDE 中用户已选用的模型）旁边，做两件宿主自己做不到的事：

1. **沉淀**：从日常交互的反馈信号中挖掘「踩过的坑、被纠正的偏好、验证有效的做法」，经 Harness-RSI 学习闭环提炼为程序性记忆（知识条目 / 技能 / 禁止项）；
2. **触达**：在后续相关任务中，把记忆**自动**送到宿主模型的上下文里——无需用户手动维护规则文件，也无需显式调用工具。

「RSI」取自 **Recursive Self-Improvement（递归自我改进）**，走 Harness-RSI 路线：不改模型权重，把包裹模型的 Harness（在 v3.0 中 = 记忆内容与触达策略）作为可写面，从执行轨迹中挖掘失败模式，自动生成最小化改进提案，经校验与人工确认后晋升，可一键回滚。

### 与 v2.6 的本质区别

| 维度 | v2.6（自持 Pipeline） | v3.0（宿主记忆层） |
|------|----------------------|--------------------|
| 答案生成者 | RSI Boot 自配模型（需 API Key） | 宿主模型（透传，零 Key） |
| 记忆作用对象 | 仅 rsi_query 的调用方 | 宿主模型的每次相关任务 |
| 触发方式 | 显式/宿主调用 rsi_query | 规则文件自动注入 + 宿主自动调用 rsi_recall |
| 模型路由/成本 | 核心能力 | 无作用对象，移除主链路 |
| 离线 LLM 任务 | 必需 | 可选增强（无 Key 时规则式降级） |

### 产品 slogan

> *Your AI remembers what worked — and what failed.*

### 设计原则

- **零 Key 可用**：全部核心功能不依赖任何 LLM/Embedding API；配 Key 仅解锁增强项，永不阻塞主流程
- **零手动维护**：记忆的沉淀与触达全自动；用户唯一的主动操作是审批（提案/草稿确认，可关）
- **宿主无关**：记忆以标准形态产出（MCP 工具 + 通用规则文件），不绑定特定 IDE；Cursor 规则文件为一等载体，AGENTS.md 托管块为通用兜底
- **零运维**：全部数据存本地 SQLite（`~/.rsi/rsi.db`），无外部服务
- **稳定**：本地依赖故障时优雅退化（记忆不可用时宿主正常工作，只是「没有加成」）

## 2. 目标用户

| 用户角色 | 核心诉求 | 使用方式 |
|----------|----------|----------|
| **开发者** | 宿主 AI 记住项目约定与历史坑点，越用越顺手 | IDE 宿主（Cursor 等）内正常工作，记忆自动生效 |
| **测试工程师** | 宿主生成的用例自动遵守历史纠偏（覆盖率要求、断言风格） | 同上 |
| **产品经理** | 宿主生成的文档自动套用历史确认的模板与措辞偏好 | 同上 |

> 均为同一人的不同角色侧面。「角色」仅用于记忆的组织与过滤，无权限语义。

## 3. 核心场景

### 场景 A：经验自动复用（核心场景）

> 用户上周适配 MySQL 时被纠正过三次（「禁止 SELECT *」「分页必须用键集游标」「时间字段一律 UTC」）。本周用户在 Cursor 里让宿主模型适配 PostgreSQL，宿主上下文中自动带着这三条禁止项，产出直接规避。

**机制**：纠正发生时，`rsi_feedback`（modified/rejected）落库 → 每日学习任务提炼为禁止项草稿 → 用户审批（或自动晋升）→ 写入项目规则文件 → 宿主模型后续会话自动携带。

**成功标准**：同类错误重复率 < 10%（同一禁止项被晋升后，宿主输出再次违反的比例）；记忆触达率 > 90%（相关任务中规则文件确实进入宿主上下文，以 alwaysApply/描述匹配命中计）。

### 场景 B：主动召回（按需增强）

> 用户开始一个不命中任何规则文件的任务（如「设计订单库的归档方案」），宿主模型判断需要历史经验，自动调用 `rsi_recall` 获取相关记忆（过往归档方案的采纳记录、被否决的方案及原因），融入自己的回答。

**成功标准**：rsi_recall 召回内容被宿主引用的比例 > 60%（以反馈/采纳信号估算）；召回延迟 P99 < 200ms。

### 场景 C：跨项目偏好沉淀

> 用户在项目 A 形成的通用偏好（如「测试一律 pytest 风格」）沉淀为全局记忆，切到项目 B 时自动生效；项目 B 的专有记忆（如其特有的部署禁忌）只在项目 B 内生效。

**成功标准**：跨项目切换零配置；项目间记忆隔离 100%（专有记忆不泄漏到其他项目的规则文件）。

### 场景 D：自我改进可审计

> 用户随时可通过 `rsi_review` 查看系统「学到了什么、打算改什么」：待审提案列表、每条提案绑定的失败证据、晋升后的观察期表现；不认可可拒绝或一键回滚。

**成功标准**：每条自动变更可溯源到具体失败样本；回滚后 1 分钟内宿主上下文恢复原状（规则文件重写）。

## 4. 功能优先级 (MoSCoW)

> v3.0 重排：M1 即交付「零 Key 记忆闭环」最小可用形态。原 v2.6 的模型调用层相关需求整体移入附录 B（可选增强，非本版交付目标）。

### M1：记忆闭环最小形态（2 周）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| rsi_recall 工具 | 记忆召回入口：task 描述 → 相关知识/技能/禁止项；描述驱动宿主自动调用 | P0 |
| 规则文件注入器 | 学习产出自动写 `<project>/.cursor/rules/rsi-*.mdc` + AGENTS.md 托管块；变更即重写 | P0 |
| rsi_feedback 工具 | 显式评分 + 隐式行为上报（沿用 v2.6 §4.2 协议） | P0 |
| 交互事件日志 | recall/feedback 事件落 SQLite（沿用 interaction_logs 表结构） | P0 |
| 规则式知识提取 | modified→修改稿沉淀；rejected+comment→禁止项；rating≥4→高分问答（每日任务） | P0 |
| 人工审批流 | 知识草稿与 Harness 提案的 approve/reject（rsi_knowledge_review / rsi_review 沿用） | P0 |
| 失败模式挖掘 | 负信号分桶（intent×strategy），SQL 实现（沿用） | P0 |
| 模板化提案生成 | 失败桶 → 最小化单槽位提案（规则模板，无 LLM） | P0 |
| 配置快照与回滚 | 晋升即快照、回滚即切换（沿用 v2.6 §3.9 Genome 机制） | P0 |
| 数据脱敏 | 记忆落库与规则文件外写前执行十条规则脱敏（沿用 §8.1） | P0 |

### M2：学习深化（2-3 周）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 召回策略学习 | Thompson Sampling 作用于召回参数臂（top_n/阈值/禁止项置顶与否），反馈驱动 | P1 |
| 用户画像 | 角色/偏好/兴趣标签（沿用 §3.8，输入改为反馈与召回事件） | P1 |
| 项目自学习 bootstrap | 扫描文档/配置生成初始记忆（沿用 scanner，输出改走审批流） | P1 |
| 观察期巡检 | 晋升后 7 天采纳率下降自动回滚（沿用） | P1 |
| 宿主辅助提炼 | 客户端支持 elicitation 时，反馈当场请宿主总结教训（零 Key 高质量提取） | P1 |
| 记忆生命周期 | 90 天归档、拒绝稿 30 天清理、失效记忆自动下线 | P1 |
| 规则冲突检测 | 学习记忆与用户手写规则（非 rsi- 前缀）矛盾/过时/重复时提醒用户，三选一裁决（用户规则为准 / 学习记忆为准 / 两者共存）；系统绝不修改用户文件 | P1 |
| 多宿主导出 | Claude Code（.claude/skills）等额外载体 | P1 |
| rsi_stats | 记忆使用统计：触达率/采纳率/禁止项遵循率（重写统计口径） | P1 |

| 功能 | 说明 | 优先级 |

| 规则文件分级 | 禁止项 alwaysApply / 经验描述触发 / 参考 globs 挂载 | P2 |

## 5. 成功指标

| 指标 | 目标 | 测量方法 |
|------|------|----------|
| 同类错误重复率 | < 10% | 禁止项晋升后，rsi_feedback 中相同模式的 rejected/modified 占比 |
| 记忆触达率 | > 90% | 规则文件注入日志（写入即生效）+ rsi_recall 调用频次 |
| 记忆采纳率 | > 60% | 召回/注入后反馈为 accepted/copied/referenced 的比例 |
| 提案首批接受率 | ≥ 50% | 人工审批统计（沿用测试计划 §12.4） |
| 零 Key 可用性 | 100% | 无 Key 环境全量测试通过（mock/规则式路径） |

## 6. 非功能需求

- **本地零依赖**：SQLite 单文件 + 文件系统；无 Key 全流程可用
- **性能**：rsi_recall P99 < 200ms；规则文件重写 < 1s；宿主启动无感
- **安全**：记忆落库与规则外写前脱敏；规则文件注入面防提示词注入（产出经审批闸门 + 内容过滤）
- **可审计**：所有自动变更可溯源、可回滚；事实日志 append-only

## 7. 约束

- 仅 stdio 传输；无 HTTP 服务端
- 数据全部在本机；规则文件写在项目目录内（用户可见可改，改动会被下次重写覆盖——文档中明示）
- 不训练模型、不调用宿主模型（协议不支持且 sampling 已废弃，SEP-2577）

## 8. 竞品对比

| 维度 | Superpowers | mem0 类记忆 MCP | RSI Boot v3.0 |
|------|-------------|----------------|---------------|
| 记忆来源 | 作者预打包 | 对话抽取 | **反馈信号 + 失败挖掘 + 回归验证** |
| 自动触发 | 技能清单（插件） | 工具调用 | **规则文件注入 + 工具调用双通道** |
| 改进闭环 | 无（静态） | 有（黑盒） | **Harness-RSI（提案/门禁/快照/回滚，白盒可审计）** |
| API Key | 不需要 | 通常需要 | **不需要（增强项除外）** |

## 9. 风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 宿主不自动调用 rsi_recall | 中 | 中 | 双通道：规则文件注入为确定性主通道，工具召回为补充；工具描述持续调优 |
| 规则文件被宿主忽略 | 低 | 中 | 禁止项 alwaysApply 兜底；触达率指标监控 |
| 记忆污染（错误学习） | 中 | 高 | 审批闸门默认开启；观察期自动回滚；快照一键恢复 |
| 规则文件与用户手写规则冲突 | 中 | 中 | 独立命名空间（rsi-* 前缀 + 托管块标记）防误覆盖；冲突检测器识别矛盾/过时/重复并提醒用户裁决（M2），系统绝不修改用户文件 |
| 用户改用非 Cursor 宿主 | 中 | 中 | AGENTS.md 通用托管块兜底；多宿主导出列 M2 |

## 附录 B：可选增强层（配 Key 启用）
